# 28. 비주얼 방향 확정 및 View 구조 검토

기준일: 2026-10-23. **시각적 목표는 사용자 승인, 렌더링 기술은 미확정.** 이번 작업은 문서 수정과 소스/설정 검토다. 최종 픽셀 아트, View 코드 추출, 새 비교 씬, 렌더러 전환, 전투 코드 변경은 수행하지 않았다.

## 1. 승인된 목표와 보존할 규칙

> 약 4등신 캐릭터와 입체감 있는 쿼터뷰 환경으로 구성한 2.5D풍 픽셀 아트 RPG. 레인 없는 전방 중심 자유 자동전투를 사용하며 카메라 방향은 고정한다.

현대적인 수제 도트와 캐릭터의 체형/무기 자세, 바닥과 벽의 면, 기둥 전후 가림, 발 그림자, 공간 깊이와 높낮이를 함께 읽을 수 있어야 한다. 약4등신은 인물형 캐릭터의 기준이며 슬라임 등 모든 몬스터를 같은 비율로 만들라는 뜻은 아니다. 정확한 픽셀 크기/PPU/기준 해상도/방향 수는 미정이다.

- 순수 C# 고정 틱 전투와 테스트, 전방 중심의 자유 자동 이동, 밀집·넉백·발 중심 충돌을 유지한다.
- 일반전과 보스는 같은 이동·카메라 구조를 쓴다. 보스 돌진/휩쓸기/재교전과 **수동 집중 방어**를 보존한다. 이전 자동 돌진 회피를 기본으로 복구하지 않는다.
- 카메라 방향 고정은 게임 도중 회전하지 않는다는 뜻이다. 처음부터 기울여 배치한 카메라를 금지하거나 Orthographic/Perspective 중 하나를 확정하는 뜻은 아니다.
- 높낮이는 우선 표현 목표다. 실제 계단/다층 전투/고저차 피해·사거리/점프/낙하는 이번 범위가 아니다. 전투 가능한 바닥은 기존 제한된 논리 평면을 유지한다.

## 4. View 기술 비교와 권고 — 아직 채택하지 않음

| 후보 | 장점 | 비용/검증 위험 | 판단 |
|---|---|---|---|
| A. 2D 캐릭터+쿼터뷰 타일/레이어 환경 | 현재 Universal2D와 가깝고 변경 범위가 작음. 면/그림자/가림으로 공간감 표현 가능 | 높낮이와 기둥 가림은 아트·분할·정렬에 의존. 평면 바닥에 캐릭터만 붙이는 것으로 목표 달성 불가 | 기존 기술을 유지하는 비교 기준으로 적합 |
| B. 2D 픽셀 캐릭터+단순3D 환경+고정 각도 카메라 | 바닥/벽/기둥의 실제 면과 공간 깊이를 검증하기 좋고 캐릭터 수제 도트 유지 가능 | 스프라이트/메시의 깊이·투명 정렬, 조명·그림자·픽셀 밀도 통일, 렌더러 호환성 검증 필요 | **최종 목표를 위한 우선 검토 후보로 권고** |
| C. 3D 캐릭터/환경을 픽셀 스타일로 렌더 | 다양한 방향/조명/높이 표현에 유연 | 캐릭터 제작/리깅/셰이더/픽셀화의 별도 공정. 수제 도트 목표와 일치 여부 추가 검증 | 현재 전투 프로토타입 이후 첫 선택으로는 비용이 큼 |

B를 권고하는 이유는 명시된 깊이/높낮이를 작은 공간 블록으로 먼저 판단할 수 있기 때문이다. 이는 2.5D가 반드시3D 환경을 요구한다거나 A로 달성 불가능하다는 뜻은 아니다. A와B를 같은 구도에서 비교하고 목표 충족/제작 부담/모바일 측정으로 선택한다. 성능 우열은 측정 전 단정하지 않는다.

B 검토 시 기존2D Renderer에서3D의 조명/그림자/투명 깊이 처리가 원하는 대로 된다고 가정하지 않는다. URP Universal Renderer 등을 **격리된 비교 씬의 후보 설정**으로 평가한다. 프로젝트 전역/품질 설정을 일괄 변경하거나, 다중 카메라 혼합/커스텀 렌더패스를 선제 도입하지 않는다. 고정 각도 Orthographic을 첫 비교 가정으로 권고하되 최종 투영 선택은 미정이다.

## 5. 승인 후 최소 View 분리 제안

다음 이름은 책임 설명용이며 현재 존재하는 클래스나 즉시 생성할 목록이 아니다. 공용 View 하나가 필요할 때부터 추출한다.

```text
CombatSimulation / StageEncounter (고정 틱, 기존 전투 그대로)
       │ 읽기: Position, Aim, AttackAim, CurrentAttack, HP, GuardActive, 보스 경로
       ▼
View 좌표 변환 → Actor 표시 / 바닥 경고 / 피드백 위치 / 고정 카메라
       ▲
방어 버튼 → 기존 RequestBossGuard() → 다음 고정 틱에서 소비
```

- 논리 좌표는2D Point로 유지한다. A는 논리(X,Y)를2D 쿼터뷰 화면에 투영, B는(X,0,Y) 지면으로 매핑하는 방식을 비교한다. 실제 공식/축척은 비교 씬에서 조절한다. 둘 다 화면의 전방/후방 의미와 벽·후퇴 한계를 동일하게 보이게 해야 한다.
- Actor의 발 중심을 Root 기준으로 두고, Visual 자식에 몸체/무기/애니메이션 높이·피격 반응을 둔다. 높이/그림자/도트 스냅은 표시 값이며 Fighter.Position에 쓰지 않는다. View Physics가 피해/길막/타겟을 다시 계산하지 않는다.
- 방향은 이동 벡터가 아니라 기존 Aim, 공격 중에는 고정 AttackAim을 투영해 선택한다. 앞/뒤/좌/우 구분으로 먼저 확인하고4방향이 사선 가독성을 충족하지 못할 때8방향 제작을 검토한다. 방향 수는 미확정이며 View가 조준을 되돌려 쓰지 않는다.
- 베기/찌르기/돌진/휩쓸기의 경계점을 **논리 공간에서 구한 뒤 동일 변환으로 투영**한다. 비등방 투영 후 각도/반경을 그대로 다시 그리면 판정과 달라질 수 있다. 검기는 시각 효과이며 적중·유효 시간·대상 수를 정의하지 않는다.
- A는 발 기준 정렬과 몸/무기 묶음(SortingGroup 등)을 검토한다. 그룹 내부 상대 순서와 개체 간 순서를 분리하고 동일 깊이는 생성 순서 등 안정적인 기준을 둔다. 기둥은 필요한 전경/후경 분리나 가림 완화로 처리한다. B는 메시 깊이와 투명 스프라이트 정렬을 실제 카메라로 확인하며 전역Y정렬을 그대로 이식하지 않는다.
- 피해 숫자/스파크/검기/타겟 마커/체력바도 같은 변환과 발 기준을 공유한다. 숫자는 변환된 화면 위치에 띄우고, 방어는 GuardActive/GuardedHits를 읽어 표시한다. VFX on/off가 시뮬레이션·시드·입력 틱을 바꾸지 않아야 한다.
- 픽셀 밀도·PPU·Point 필터·기준 해상도/정수 배율을 함께 실험한다. Pixel Perfect 기능 유무만으로3D 환경과2D 캐릭터의 밀도가 자동 통일된다고 가정하지 않는다. 논리 좌표를 도트 격자에 반올림하지 않는다.

## 6. 승인 후 실제 Unity 비교 체크리스트

최소 단위는 같은 논리 시드/설정/입력 틱을 사용하는 영웅1·근접 적1·보스1 비교, 바닥/벽/기둥/단차 외형 한 구간이다. 임시4등신 실루엣과 최소 방향 표시만으로 시작한다. 최종 아트·전체 애니메이션 세트는 아직 제작하지 않는다.

| 검증 장면 | 통과 기준 |
|---|---|
| 1. 약4등신과 입체 공간 | 머리/몸/무기 비율, 발 접지, 바닥·벽·기둥의 전후/상하면이9:16에서 읽힘 |
| 2. 전방 접근·자유 이동 | 적이 화면 전방에서 접근. 사선/측면 이동이 레인이나 부유처럼 보이지 않음. 경계/발 충돌은 기존과 동일 |
| 3. 밀집·넉백 | 5→8→12에서 앞뒤가 읽히고 몸·무기 부품이 섞이지 않음. 그림자는 발을 따르며 사망자는 논리 판정에서 제외 |
