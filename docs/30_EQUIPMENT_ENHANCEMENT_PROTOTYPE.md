# 30. Milestone 2 — 장비·강화 최소 플레이 기능

기준일: 2026-10-23. 사용자 승인 범위는 **장비를 강화하면 실제 전투 결과가 달라지는 최소 기능**이다. 전투 프로토타입1차 구현을 기반으로 장비 장착·강화·재도전을 연결하며 전투 패턴/회피/레벨/퀘스트/자동 스킬2슬롯/새 무기별 스타일/비주얼 고도화는 추가하지 않는다.

## 1. 현재 스탯·피해 흐름과 연결 지점

기존 `CombatPrototype.Restart`는 Inspector Hero Health/ Hero Damage 및 CombatDamageDefinition의 Hero Defense를 Fighter 생성자에 넣었다. 개별 적중은 기존 DamageProfile의 피해 범위→동작 계수/치명타→반올림→DEF 차감→최소1을 유지한다. 공격 기하/콤보/이동/수동 집중 방어는 바꾸지 않는다.

이번에는 전투 시작 시 **기본 HP·ATK·DEF + 장착 장비 보너스**를 불변 값으로 계산해 같은 Fighter 생성자에 전달한다. 이미 시작한 전투 중 장비를 교체/강화해도 그 Fighter의 스탯은 바뀌지 않는다. 작업대의 Apply equipment / retry는 현재 전투를 중단하고 HP/시간/콤보/적을 초기화한 새 전투다. 층 도중 무료 회복이나 실시간 장착 시스템으로 해석하지 않는다.

## 2. 데이터·상태·계산의 분리

| 위치 | 책임 |
|---|---|
| `Assets/Scripts/Progression/PrototypeEquipment.cs` | 순수 C# EquipmentSpec/EquipmentInstance, 장착1무기/1방어구, 전투 스탯 합산, EnhancementPolicy, session wallet/강화 난수/재료 테스트 보상 중복 방지 |
| `Assets/Scripts/Progression/EnhancementTower.Progression.asmdef` | Unity 표현/전투에서 독립된 성장 계산 어셈블리 |
| `Assets/Scripts/Data/EquipmentPrototypeDefinition.cs` | 정적 목록·강화 확률/비용/초기 재료·별도 강화 시드를 작성하고 실행 시작에 스냅샷 생성 |
| `Assets/Data/PrototypeEquipment.asset` | 위 정적 정의의 초기 비교 값. 강화 레벨/실패 보정/재료를 런타임에 쓰지 않음 |
| `Assets/Scripts/Presentation/CombatPrototype.cs` | 기존 전투 조립에 선택형 장비 세션/작업대 UI/다음 전투 스탯·결과 비교 연결 |
| `Assets/Scenes/EquipmentPrototype.unity` | 기존 CombatViewComparison의 설정/표현을 복사한 별도 장비 실험 씬 |
| `Assets/Tests/EditMode/EquipmentTests.cs` | 장착·강화·재료·시드·실제 피해 변화의 자동 회귀 검증 |

EquipmentSpec은 식별자/이름/슬롯/기본 보너스/강화당 증가량을 가진 불변 정의다. EquipmentInstance는 정의 참조와 강화 단계·실패 횟수를 가진 세션 실행 상태다. 상태는 아이템별로 유지하고 교체/해제해도 강화/실패 보정이 사라지지 않는다. 슬롯 교체는 합산 중첩 대신 해당 슬롯의 장비를 대체한다.

장비 실험은 시작 아이템4개만 제공한다. 무기는 모두 장검 기본 콤보를 쓰며 Iron/Steel의 스탯 비교다. 대검 프로필 전환·드랍·등급/개체값·반지/오브/자동 스킬·계승·인벤토리 확장·거래는 구현하지 않는다.

## 3. 조절 가능한 프로토타입 가정 — 확정 밸런스 아님

| 장비 | 기본 보너스 | 강화1단계당 보너스 |
|---|---|---|
| Iron longsword | ATK4 | ATK2 |
| Steel longsword | ATK8 | ATK1 |
| Iron armor | HP40/DEF1 | HP10/DEF1 |
| Leather armor | HP80/DEF0 | HP20/DEF0 |

합산은 고정 보너스의 선형 비교 실험이다. 최종 강화 성장 곡선/경제/무기 밸런스를 확정하지 않는다. 입력 기본값과 상한 검사는 기술적 범위 검증이며 게임의 강화 최대 단계를 새로 정한 것이 아니다.

- 시작 Gold200/강화석20, 강화 난수 시드8241. 전투 시드와 강화 난수를 분리한다.
- 기본 성공률 `max(10%, 60% - 현재 강화 단계 × 3%p)` + 실패 횟수 ×1%p, 최대100%. 정확한 기본 확률 곡선은 이번 비교를 위한 가정이다.
- 비용 Gold `10 + 현재 강화 단계 ×5`, 강화석1. 성공/실패 모두 시도1회 비용을 차감한다. 재료 부족이면 난수/단계/실패 보정/재료를 변경하지 않는다.
- 성공 +1, 성공 중2.5% 축복은 **총 +2**, 실패 횟수는 성공/축복에0으로 리셋한다.
- 실패는 단계 유지, 실패 중1% 역행은 -1(최소0). 역행도 실패 보정을 유지·누적한다. 장비는 파괴하지 않는다.
- 확률은 [13](13_ENHANCEMENT.md)의 구조를 따르며 v0의1%p/2~3%/1%는 이번에 조절 가능한 기본값으로만 사용한다. 단계별 최종 비용·수치는 미확정이다.

## 4. 최소 플레이 흐름

`EquipmentPrototype`은 작업대를 먼저 보여준다. 장비 선택/강화→다음 전투의 ATK·DEF·최대HP 확인→Apply equipment / retry로 전투를 시작한다. 전투에서 Equipment / forge를 열면 시뮬레이션이 멈춘다. 장착·강화 후 다시 적용하면 같은 모드/적 설정/고정 전투 시드의 새 전투가 시작된다.

작업대는 현재 전투의 시작 스탯→다음 시작 스탯, 아이템별 단계/보정 포함 성공률/필요 Gold·강화석, 시도 결과, 이전 전투의 종료/중단 상태·경과 시간·시작 스탯·실제 적HP 감소 누적·처치 수를 보여준다. 임의 가중치의 '전투력 점수'로 실제 결과를 대신하지 않는다. 이전 기록은 바로 전 런이며 재시작할 때 갱신된다. STOPPED와 CLEAR/DEFEAT를 구분하고, 같지 않은 모드끼리의 기록을 동일 조건 비교로 주장하지 않는다.

재료가 부족할 때 **Material test (1 foe)**로 일반 적1명을 처치하면 Gold40/강화석3을 해당 런에1회 지급한다. 사망/중단은 지급하지 않고 Update 반복으로 중복 수령하지 않는다. 반복 시작한 새 런은 다시 보상을 얻을 수 있다. 정식 Farming/무한 소환/오프라인·드랍 경제/Rage를 구현한 것이 아닌 재료 보충용 유한 전투다. 원래 도전/보스에는 이 보상을 자동 적용하지 않는다. 재료 테스트 뒤 원래 도전은1/5/8/12·Stage run·Charge boss 버튼으로 선택한다.

## 5. 저장·권위·보존 범위

**Play 세션 한정 로컬 프로토타입**이다. 장비·강화·지갑은 전투 Restart/모드/표시 전환 중 유지하지만 Play 종료/씬 재로드/앱 종료 후에는 초기화한다. 저장/서버/영구 보상/오프라인 정산을 구현하지 않았다. 추후 경제·아이템·강화 RNG는 기존 서버 권위 원칙을 따라야 하며 이 로컬 세션은 최종 API/보안 계약이 아니다.

기존 CombatPrototype/CombatViewComparison 씬은 그대로 두고 새 씬에서만 장비 기능을 활성화한다. 기존 장비 비활성 전투의 스탯/시드 흐름은 유지한다. 사용자가 조정한 원본 씬 값을 덮어쓰지 않고 새 씬 생성 시 복사한다. 레벨·스킬2슬롯·2.5D 최종 기술 선택은 이번에 구현/확정하지 않는다.

## 6. Unity 수동 검증

1. Unity6000.6.4f1의 임포트/컴파일이 끝나면 `Assets/Scenes/EquipmentPrototype` 열기→Play. 작업대가 열리고 Gold200/Stones20 및 초기 무기/방어구 장착을 확인한다.9:16에서 스크롤로4개 아이템을 모두 볼 수 있어야 한다.
2. 장비를 해제/교체하며 Next run ATK/DEF/HP만 변하고 현재 전투 시간/HP는 진행하지 않는지 확인한다. Apply equipment / retry→1 foe 또는 Charge boss에서 초기 피해/처치 시간/생존을 본다.
3. Equipment / forge→장착한 무기 Enhance. 결과와 단계/성공률/비용/재료 변화를 확인한다. 성공 시 다음 ATK 증가, 실패 시 유지·보정 증가를 본다. 방어구는 HP·DEF가 변한다. 축복/역행은 낮은 확률이므로 자동 테스트로 확인하거나 임시 정의값을 조절해 비교한 뒤 복원한다.
4. Apply equipment / retry로 같은 전투를 시작한다. 이전 결과와 실제 HP 감소/처치 시간·생존을 비교한다. 장비마다 모든 지표가 반드시 좋아진다고 단정하지 말고 같은 모드/설정인지 확인한다. 최소 피해/치명타/넉백·상태 변화 때문에 일부 타격값이 같을 수 있다.
5. 재료가 부족하면 Material test→처치→장비 화면 복귀. 런당40G/3강화석이1회 지급되는지, 같은 런에서 기다리거나 작업대를 다시 열어도 재지급되지 않는지 확인한다. 기존 재료/강화는 Restart에도 유지되어야 한다.
6. 수동 집중 방어·기존 View/Sword motion 전환·Stage run이 유지되는지 확인한다. Play를 종료하면 장비 세션은 초기화된다. 영구 저장으로 오해하지 않는다.
7. 기본값 조절은 Play 종료 후 `Assets/Data/PrototypeEquipment`에서 한다. 기존 Hero Health/Damage/CombatDamage Hero Defense는 장비 전 기본 스탯이다. 새 씬이 없을 때만 `Enhancement Tower → Create Equipment Prototype Scene` 메뉴를 사용한다. 기존 장비 씬이 있으면 열기만 하며 덮어쓰지 않는다.

## 7. 검증과 다음 최소 단계

- 검증 결과는 작업 종료 시 아래에 기록한다. 구현과 미검증을 구분하며 코드 컴파일/테스트를 Play 체감이나 기기 성능으로 대체하지 않는다.
- 정식 장비 저장/불러오기, 재료 드랍·지속 Farming, 전투 결과 정산, 정식 보상 UI, 서버 경제, 레벨/퀘스트/스킬2슬롯, 새 전투 패턴은 미구현이다.
- 다음 최소 단계는 사용자가 같은 상대에 대한 강화 전후 차이와 재료 보충 흐름을 확인한 뒤, 장비 세션의 로컬 저장/불러오기 또는 정식 전투 결과 정산 중 한 단위를 선택하는 것이다. 서버나 전체 인벤토리를 미리 확대하지 않는다.

### 이번 검증 결과

- 임시 Unity6000.6.4f1에서 신규 Progression/데이터/Presentation/Editor 어셈블리 컴파일과 Unity가 작성한 meta·정의/씬 생성을 확인했다. 초기 씬 생성에서 정의 에셋 참조가 전환 중 누락된 문제를 저장 후 재로드로 수정하고, 최종 씬의 참조 및 실제 Play 초기화를 재검증했다.
- **Unity Test Runner EditMode95/95 통과**(기존87 + 신규8). 슬롯 대체/해제 후 강화 유지, 성공/축복/실패/역행·0단계 하한·실패 보정/천장, 재료 부족/잘못된 난수의 무차감, 아이템별 독립 보정·시드 재현, 재료 보상 중복 방지, 무기/방어구 강화 후 실제 전투 피해 증가/피해 감소·기존 전투 불변성과 정의 유효성을 확인했다.
- 임시 Unity Play 검증기에서 작업대 일시정지→무기/방어구 강화→새 Fighter 스탯 반영·같은 시드의 실제 적 피해 증가→재료 테스트 처치·보상1회→Restart 후 강화 유지와 정적 에셋 불변성을 확인했다. 검증은 명시적 메서드 호출로 실행했으며 실제 GUI 클릭·터치 체감 검증을 대신하지 않는다.
- 장비 실험의 클리어/패배 후 전투 시간은 동결한다. 기존 전투 시뮬레이션 코드는 수정하지 않고 Presentation에서 진행을 중단한다. 재료 보상도 이후 Update에서 중복되지 않는다.
- 초기화/환경 렌더를 Metal 카메라 캡처로 확인했다. IMGUI 작업대 자체는 카메라 캡처 대상이 아니며 UI 스크롤/버튼의 실제 터치,9:16/9:19.5 최종 가독성·사운드 청취·모바일 성능·Android 빌드·Windows는 미검증이다. 배치 Editor의 Search 인덱서 내부 예외는 게임 코드와 분리했다.
- 장비 해제/교체는 현재 스탯 보너스만 바꾸며 캐릭터 의상/검 외형은 기존 임시 View를 유지한다. 공식 장비 외형·무기별 동작 제작은 이번 범위가 아니다.
